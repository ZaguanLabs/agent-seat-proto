# Tier 0.5 X11 input verification

Status: local experimental milestone evidence, 2026-08-09.

## Subject and environment

- `agent-seat-proto` 0.1.3, wire revision 5
- `agent-seat-mcp` 0.1.4
- `agent-seat-x11` 0.1.22
- `agent-seat-settings` 0.1.6
- Openbox 3.6.1
- Xvfb from Mageia `x11-server-xvfb-21.1.23-1.mga10`
- Rust/Cargo 1.85.0

No package was installed and no person's desktop display was used. Each
process test creates a private runtime/configuration directory and a fresh
isolated Xvfb/Openbox display.

## Verified behavior

The public provider lifecycle test proves:

- every provider instance starts with its volatile seat disabled;
- an opening handshake is refused while disabled;
- explicit Enable admits a new session;
- Disable revokes the old generation and restart returns to disabled;
- a client-relative pointer movement reaches the independently queried X11
  root coordinate;
- primary, middle, and secondary clicks produce matching complete X11 button
  press/release pairs at that target point;
- a topmost override-redirect window covering the point causes refusal;
- over-bound root-child and fragmented input-shape evidence fails closed;
- keyboard text is refused while another window owns input focus;
- after the target owns focus, `aA` plus Return and Tab produces four completed
  scalar actions and all five X11 key press/release pairs (including Shift)
  through the server's live keyboard mapping;
- a scalar absent from the live map is refused before any key event; and
- the welcome advertises `input_injection` but not `human_activity`.

The protocol and translator tests additionally prove closed schemas, separate
`input_pointer`/`input_keyboard` grants, nonempty text, rejection of unsafe
control characters, the 256-action bound, strict unknown-field rejection, and
one-to-one MCP-to-wire translation for all three input tools.

The focused commands used during implementation were:

```sh
cargo test -p agent-seat-proto --lib --offline
cargo test -p agent-seat-mcp --all-targets --offline
cargo test -p agent-seat-x11 --all-targets --offline
cargo test -p agent-seat-x11 --test systemd_input_confinement --offline -- \
  --ignored --exact provider_loses_input_devices_while_delegated_application_keeps_baseline
```

The last command passed on the recorded host without root or package changes.
It proves the existing rootless private-device service fixture hides
`/dev/input` and `/dev/uinput` from the provider-side process while preserving
the separately launched application's baseline device namespace. It supports,
but does not by itself complete, the profile's negative-authority fixture.

The repository-wide gate is recorded only after all workspace commands in
`AGENTS.md` pass for the final source tree.

## Exact limitation

This evidence proves only bounded XTEST requests against a fresh target and
the result observed at the X11 boundary. It does not prove that an application
accepted or rendered input. It does not identify physical activity or prevent
a person's event from overlapping an agent action. Same-user X11 processes can
also bypass Agent Seat independently. The volatile seat is practical operator
consent and a later-request kill switch, not mandatory mediation or Tier 1
authority.
