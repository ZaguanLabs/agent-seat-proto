# Tier 0.5 input v2 verification

Date: 2026-08-09. Status: local reference-implementation evidence for an
experimental profile; not independent conformance evidence.

## Subject

- `agent-seat-proto` 0.1.5, local JSON wire revision 7;
- `agent-seat-mcp` 0.1.7, MCP `2025-11-25` and `2026-07-28` projections;
- `agent-seat-x11` 0.1.27, XKB/XTEST realization; and
- `agent-seat-settings` 0.1.8, broadened `input_keyboard` grant description.

The profile under test is
[`agent-seat.x11-tier0.5-input.v2`](../protocol/profiles/x11-tier0.5-input-v2.md).

## Environment

- Mageia 10 development host, Linux 6.18.35-desktop-1.mga10;
- Rust 1.85.0;
- Xvfb from `x11-server-xvfb` 21.1.23-1.mga10;
- released Openbox 3.6.1;
- `setxkbmap` 1.3.4; and
- isolated test displays, never the operator's live Openbox display.

## Observed evidence

The complete repository gate passed:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --all-targets
cargo doc --workspace --no-deps
```

The assertions, rather than log text, establish the following observations:

- strict wire validation accepts a typed Control+L request and rejects
  duplicate or noncanonical modifiers;
- every one of the 63 MCP schema key names deserializes to the wire enum, while
  both MCP eras retain closed object schemas;
- the legacy MCP surface contains 17 tools and the modern surface contains 18,
  including `seat_release`;
- a synthetic XKB type in which Control changes the selected level resolves
  the final chord as a whole, not as a key followed by blindly added modifier
  state;
- on isolated Xvfb/Openbox, Control+L produces two balanced press/release pairs
  and Page Down produces one balanced pair for the already focused fresh
  target;
- focus moved away before Page Up produces `invalid_argument` and no input
  event; and
- the existing Norwegian XKB application-visible
  `https://slashdot.org` regression remains exact.

The provider lifecycle binary ran 24 tests successfully. Its explicit
all-installed-layout matrix and private-device Bubblewrap gates remained
ignored by the ordinary workspace command, as their test annotations require.
All other workspace tests passed.

## Limits and inference

The balanced X11 events prove only what the provider queued and synchronized;
they do not prove that Brave or another application interpreted a shortcut.
The live named-key process fixture uses the test display's default layout. The
custom modifier-level case is deterministic unit evidence, while the Norwegian
process fixture covers text rather than every named key. No exhaustive
named-key matrix over every installed XKB layout was run for this milestone.

The profile remains experimental. Browser media back/forward keysyms, held
keys, repeats, macros, arbitrary sequences, forced focus, compose/IME, output
capture, physical-user priority, and general application acceptance are not
implemented or claimed. The version-2 profile's missing-modifier and
every-partial-injection cleanup fixtures remain required before a complete
conformance report.
